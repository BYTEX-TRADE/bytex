# 0003 — Domain model

Status: accepted

## Problem

Strategies, engines, adapters, and the backtester all need one vocabulary for
instruments, market data, orders, positions, and accounts. The model must be
rich enough to express what real venues support and strict enough that invalid
states are unrepresentable.

## Decision

The model lives in `Bytex.Core.Model` and is organised in six groups.
Everything is immutable except `Order`, `Position`, `Account`, and `OrderBook`,
which are aggregates that evolve by applying events.

### 5. Orders and execution (`Bytex.Core.Model.Orders`, `.Events`)

`Order` is an aggregate with a finite state machine. Every transition is caused
by an `OrderEvent` and recorded in the order's event list.

```csharp
public abstract class Order
{
    TraderId TraderId; StrategyId StrategyId; InstrumentId InstrumentId;
    ClientOrderId ClientOrderId; VenueOrderId? VenueOrderId; PositionId? PositionId;
    AccountId? AccountId; OrderSide Side; OrderType Type; Quantity Quantity;
    TimeInForce TimeInForce; UnixNanos? ExpireTime; OrderStatus Status;
    Quantity FilledQuantity; Quantity LeavesQuantity; decimal? AvgPx; decimal Slippage;
    bool IsReduceOnly; bool IsPostOnly; bool IsQuoteQuantity; Quantity? DisplayQuantity;
    ContingencyType Contingency; OrderListId? OrderListId; IReadOnlyList<ClientOrderId> LinkedOrderIds;
    ClientOrderId? ParentOrderId; ExecAlgorithmId? ExecAlgorithmId; TriggerType EmulationTrigger;
    IReadOnlyList<string> Tags; IReadOnlyList<OrderEvent> Events; IReadOnlyList<TradeId> TradeIds;

    void Apply(OrderEvent e);   // validates transition, mutates, appends
    bool IsOpen, IsClosed, IsInflight, IsActiveLocal, IsEmulated, IsBuy, IsSell, IsPassive, IsAggressive
}

sealed class MarketOrder, LimitOrder (Price), StopMarketOrder (TriggerPrice, TriggerType),
             StopLimitOrder (Price, TriggerPrice), MarketIfTouchedOrder, LimitIfTouchedOrder,
             TrailingStopMarketOrder (TrailingOffset, OffsetType, ActivationPrice?),
             TrailingStopLimitOrder (+ LimitOffset), MarketToLimitOrder
sealed class OrderList(OrderListId Id, IReadOnlyList<Order> Orders, Order First)
```

Valid transitions (the state machine rejects anything else):

```
Initialized → Denied | Emulated | Submitted
Emulated    → Canceled | Expired | Released
Released    → Denied | Submitted
Submitted   → Accepted | Rejected | Canceled | PartiallyFilled | Filled | PendingUpdate | PendingCancel
Accepted    → Canceled | Expired | Triggered | PendingUpdate | PendingCancel | PartiallyFilled | Filled
Triggered   → Canceled | Expired | PendingUpdate | PendingCancel | PartiallyFilled | Filled
PendingUpdate → Accepted | Canceled | Expired | Triggered | PendingCancel | PartiallyFilled | Filled
PendingCancel → Canceled | Accepted | Expired | PartiallyFilled | Filled
PartiallyFilled → Canceled | Expired | PendingUpdate | PendingCancel | PartiallyFilled | Filled
```

`OrderUpdated`, `OrderModifyRejected`, `OrderCancelRejected` do not change
status; they revert a pending status to the previous one.

Events (`abstract record OrderEvent(TraderId, StrategyId, InstrumentId, ClientOrderId, VenueOrderId?, AccountId?, Guid EventId, UnixNanos TsEvent, UnixNanos TsInit, bool Reconciliation)`):

```
OrderInitialized  OrderDenied(Reason)  OrderEmulated  OrderReleased(ReleasedPrice)
OrderSubmitted  OrderAccepted  OrderRejected(Reason)  OrderCanceled  OrderExpired
OrderTriggered  OrderPendingUpdate  OrderPendingCancel  OrderModifyRejected(Reason)
OrderCancelRejected(Reason)  OrderUpdated(Quantity, Price?, TriggerPrice?)
OrderFilled(TradeId, PositionId?, OrderSide, OrderType, Quantity LastQty, Price LastPx,
            Currency, Money Commission, LiquiditySide)
```

Commands (`abstract record TradingCommand(TraderId, StrategyId, InstrumentId, ClientId?, Guid CommandId, UnixNanos TsInit)`):

```
SubmitOrder(Order, PositionId?, ExecAlgorithmId?)   SubmitOrderList(OrderList, PositionId?)
ModifyOrder(ClientOrderId, VenueOrderId?, Quantity?, Price?, TriggerPrice?)
CancelOrder(ClientOrderId, VenueOrderId?)   CancelAllOrders(OrderSide)
BatchCancelOrders(IReadOnlyList<CancelOrder>)   QueryOrder(ClientOrderId, VenueOrderId?)
```

Reports used for reconciliation (`Bytex.Core.Model.Reports`):


## Alternatives considered

- **One `Order` class with nullable fields for every type.** Rejected: the
  order type hierarchy makes invalid combinations (a market order with a limit
  price) impossible rather than merely unchecked.
- **Mutable data structs.** Rejected: data is shared across the cache, the bus,
  and many subscribers; immutability removes a class of bugs.

## Consequences

- Adapters translate venue payloads into these types and nothing else; the
  engine never sees venue JSON.
- Backtest and live produce the same event types, so reports and analytics do
  not care where an event came from.
